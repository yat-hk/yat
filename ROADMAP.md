# YAT — Roadmap

**Companion docs:** [PRD.md](PRD.md) · [ARCHITECTURE.md](ARCHITECTURE.md) · [docs/SPEC-VALIDATION.md](docs/SPEC-VALIDATION.md)

Each version has explicit exit criteria. Nothing ships to a wider audience until v0.5; v0.x is one device and brutal honesty about measurements. The engine is the project's core asset — it gets built incrementally from v0.1, never "later".

## v0.0 — Spec validation (paper, no firmware)

**Goal: know the grammar is enough before building the engine.**

- Work the SPEC-VALIDATION matrix: write every ✅ use case as an actual `.yat-pack.json` against the draft grammar — no hand-waving; log every gap with a proposed addition and cost.
- Draft `docs/PACK-SPEC.md` (agent-first formal reference) + the JSON Schema; accepted additions from the matrix (`inline` sources, `{{now}}` + date filters) folded in.
- Sketch the four v1 packs + two community-candidate packs (GMB minibus, countdown) end-to-end.

**Exit:** ≥80% of the matrix passes on paper; every failure has a named v1.x path or an explicit out-of-scope ruling; draft schema validates all sketched packs.

## v0.1 — Walking skeleton

**Goal: the full standalone loop exists and survives 48 h unattended on battery.**

- Firmware: wake → fetch HKO JSON directly → minimal engine (dot-path extraction, `column`/`text`/`bignum` widgets only) → render → refresh → deep sleep. One hardcoded spec baked into LittleFS. Hash-skip both ends of the loop.
- OTA-ready partition table from day one (`ota_0/ota_1/littlefs`) — changing it later forces USB reflash for everyone.
- Spikes to close: ext1 wake macro under pioarduino/IDF5; buzzer pin confirmation; TLS to data.weather.gov.hk with a bundled CA store (no `setInsecure()`); NTP + PCF8563 timekeeping through deep sleep; UF2 packaging of the full flash image (fallback path).

**Exit criteria (measured, written into the repo):**
- [ ] 48 h on battery, hourly refresh, no wedge
- [ ] Deep-sleep floor current (µA) measured → battery model corrected
- [ ] mAh per full cycle and per skipped wake measured
- [ ] Fetch+parse+render time and peak RAM measured against a real HKO response

## v0.2 — Scheduler, config & provisioning

**Goal: the device is fully config-driven and a fresh device can be provisioned without an IDE.**

- Config loading from LittleFS (versioned schema, validate-or-keep-last-good); on-device scheduler: per-page cadences, commute windows (weekday masks), quiet hours, playlist modes; warning-takeover check on every wake.
- Buttons: cycle / force refresh; KEY0-held → QR portal (WiFi re-provisioning).
- Serial protocols: Improv-serial (WiFi) + file protocol (list/read/write config & packs, set secrets, status dump, reboot).
- Optional `sync_url`: hash-gated pull of config + packs from a static host; WiFi fast-reconnect from RTC RAM.

**Exit:** a week purely schedule-driven incl. quiet hours + one simulated takeover; config edited over serial and via sync repo, both applied without reflash.

## v0.3 — The spec engine & packs

**Goal: the YAT Pack Spec v1 is real, and the four v1 packs prove it.**

- Full engine: path-expression grammar (`[?field=='x']`, `| [0]`, `| length`), `rss`/`csv` + `inline` sources, `{{now}}` + date filters, complete widget set (`row`/`list`/`icon`/`image`/`qr`/`bar`, `when` visibility), single-pass substitution, resource caps, standard chrome (footer: source · updated · battery/stale glyphs). **Not implemented despite the spec:** pack-scoped secrets with `sent_to` enforcement — see the backlog bullet below. **Landed 2026-08-05, later than this section implies:** the private-range block (`E_FETCH_BLOCKED`, PACK-SPEC §12.3 rule 2), in `firmware/src/yat_net.cpp`'s `fetchPackSource()`.
- Engine built as portable core; **native CLI target** (`tools/preview`: spec → PNG) running golden-file tests in CI; **parser/extractor fuzzing in CI** (hostile-input model from day one).
- Dogfood packs as specs: `hko-weather` (incl. real takeover pages), `transport-eta` (KMB/Citybus/MTR), `news-brief` (headlines mode), `image`.
- Font/icon investment: bitmap font sizes/weights in LittleFS, weather/transit/warning icon set — judged against BRAND.md.
- `docs/PACK-SPEC.md` written alongside the engine, not after it. Grammar frozen only after all four packs render from spec.

**Status 2026-07-27:** Pack engine implemented for the full 0.3 spec — image widget, `min_refresh_min`, stale-serve and the §9.9 icon artwork (all 32 catalog names, real 24×24 bitmaps generated by `tools/icons/gen_icons.py`) have all landed; firmware-side PNG decoding landed too (pngle-backed ImageDecoder with IHDR bomb guard), closing the last engine-feature gap. All example packs render in the native preview; grammar freeze gate met for exercised rows.

**Exit:** all four packs render correctly in zh-Hant/en/bilingual on device and in the CLI (pixel-identical); installing a pack = copying one JSON file; a stranger can judge screenshots against BRAND.md and nod.

## v0.4 — Voice

**Goal: push-to-talk page switching that feels acknowledged.**

- Firmware: record-while-connecting on button wake, WAV POST direct to STT (key in NVS; ElevenLabs primary), on-device s2t normalization + alias matching (en/zh-Hant/jyutping), buzzer/LED feedback (record start/stop, match, error), keyless fallback to page-cycle.

**Exit:** ≥90% match rate on the four v1 pages across Cantonese/English/Mandarin from 3+ speakers; button-to-visible ≤45 s; failed match error-beeps without refreshing.

## v0.5 — OTA, web flasher & the skill  ·  **SHIPPED 2026-08-08 as the public beta**

**Goal: strangers can do this.**

- GitHub Actions release pipeline: per-model matrix (`firmware-<model>.bin`, merged full-flash image, `.uf2`, sha256 manifest) on tag — **live since 2026-07-28**. ~~OTA direct from GitHub releases~~ — **built 2026-08-04**: portal update card (phone checks GitHub releases; device never phones home) → POST /api/update with a regex-validated tag only (never a URL) → esp_ota_* download pinned to the CA bundle (Sectigo E46 for github.com; asset CDN chains to ISRG X1), redirect suffix-pinned; rollback wired via CONFIG_APP_ROLLBACK_ENABLE with app-valid confirm at end-of-first-successful-cycle. **Live end-to-end OTA REHEARSED 2026-08-04**: throwaway release, phone-tap update card -> download -> verify -> reboot -> healthy-cycle self-confirm, all on real hardware. Known residual: unauthenticated LAN peer could trigger a downgrade to an older genuine release.
- **Website** (a separate, private codebase deployed to its own domain — flash mechanics modeled on OpenDisplay's Toolbox + Seeed's Firmware Hub), three faces: **Flash** (model picker → esptool-js, auto bootloader entry, UF2 fallback → Improv WiFi → starter config); ~~**Toolbox** (config over Web Bluetooth)~~ — **superseded**: the device serves its own settings page over the household's WiFi (§4.5), so no BLE GATT mode was built and none is planned; **Gallery** (built from `yat-packs`, param forms from pack schemas, installed from the device's own page with the machine-derived safety summary). WASM engine preview if the v0.3 feasibility check passed; otherwise ships v1.0.
- **`yat-packs` community repo** bootstrapped: CI (schema validation + golden renders, nothing from PRs executes), contribution guide, official/community structure, 2–3 seed community packs (GMB minibus as the tutorial pack).
- Skills published: **user skill** (`setup` / `configure` preview-before-push / `diagnose` via the device's own page, serial or sync) and **developer skill** (spec + widget catalog + validation matrix knowledge, preview tooling, on-device test, PR submission to `yat-packs`). `AGENTS.md` + `docs/SETUP.md` for other agents and humans.
- [ ] rotate any credentials used during early prototyping.
- yat repo secret-hygiene verified clean (2026-08-04 audit).

**Exit:** one fresh-machine test — a person who has never seen the repo goes from box to first render in <15 min using only the website; a pack installed from the gallery through the device's own page; a third-party pack lands in `yat-packs` via the developer skill's PR flow; one OTA update applied and one rollback exercised in the wild.

## v1.0 — Public launch

**Goal: announce it.**

- Hardening: stale-serve glyphs, per-source byte caps, watchdog on hung refresh, wedge-proofing month-long soak.
- Docs complete: quickstart, PACK-SPEC reference, pack authoring tutorial, troubleshooting.
- WASM preview in the flasher site (if not already shipped).
- Launch content: photos of a real device showing the T8 takeover + bus ETA pages; post for HK maker communities.

## Backlog

- **Pack-scoped secrets with `sent_to` enforcement** — specified (PACK-SPEC
  §10, §12.3 rule 4); engine and firmware do not implement it. `{{secrets.*}}`
  is refused unconditionally in every position the engine parses
  (`engine/src/text.cpp:568-570`), so no pack construct can reference a secret
  at all today — packs declaring a `secrets` block are refused at install
  (the portal's sideload-consent flow, the website's device-portal.js module)
  rather than installed against a reference that could not work. Building this for real
  needs: a legal `{{secrets.*}}` grammar position, `FetchFn` gaining a
  header/body path to carry a secret on (it currently carries only a source
  id and URL — `engine/include/yat/engine.h:134-136`), per-pack NVS storage
  distinct from the two system keys, and the `sent_to` host-match enforcement
  itself.
- **Per-profile gallery previews** — the engine renders every pack on the E1001
  mono profile (`yat-preview --profile e1001`); the gallery could show both once
  an E1001 firmware target exists (see v2 themes).
- **Voice todo — parked 2026-08-07, pending a hardware voice test.** The pack
  sits in yat-packs' `draft/` (out of the gallery, still schema- and
  render-tested); the firmware's intent layer ships but is dormant without it
  (proven on device: page routing normal, todo verbs inert). To ship: test
  add/done/clear by microphone with an LLM key, then move the pack back to
  `official/` and regenerate the gallery.

- **Release signing for OTA** — the device only downloads from this repo's
  releases over pinned TLS, but cannot yet verify authorship of the image
  itself; signing would also close the known LAN-peer downgrade residual
  (an unauthenticated setup-mode peer can trigger a rollback to an older
  genuine release).
- ~~**A drawn data-warning glyph**~~ — shipped as the INFO tier of the
  three-tier on-panel notice system (footer glyph, DEGRADED bottom strip,
  ACTION top banner; see PACK-SPEC).
- **Tide high/low labels** — HKO's HLT feed carries times and heights but no
  tide type, and the spec deliberately has no cross-item comparison to infer
  one; needs a richer source or a spec-side answer.
- **Fetch-guard follow-ups from the 2026-08-05 security audit**: IP-literal hosts
  (e.g. `https://8.8.8.8/x`) pass the schema pattern and both validators despite
  §12.3 rule 1; several §11.3 E_FETCH_* tokens describe behaviour that works but
  never appear as literal error strings; WebSerial `PUT` and the serial CLI
  bypass the portal validator entirely (a >8-source pack loads that way).
- **MTR destination names** — rows show direction words rather than the raw
  station code, but a real code→name lookup wants the v1.x `map()` filter.
